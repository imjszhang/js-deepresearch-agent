# 结构化响应解析与恢复修复

本轮按此前七阶段计划实现。目标是修复程序对模型返回结构的解释方式；证据真值、回答关系和表达忠实性仍是模型观察，工程通过不代表内容正确。

## 问题与行为

旧代码使用第一个左花括号到最后一个右花括号截取 JSON。说明文字里的括号会污染完整答案；重复返回两份合法答案也会被拼接成非法 JSON。主张校验还会重复发送相同请求，并把探索期间的失败描述为报告生成失败。

现在统一由 `structured-response.mjs` 识别完整值、候选边界、转义与嵌套。相同对象允许字段排序不同，数组次序、额外字段和数字表示保持区分。不同候选、重复对象键、截断及资源超限明确拒绝；不会拼接、补括号或提升嵌套子对象。

默认采用保守候选策略：不同 JSON 根候选即视为歧义，包括其中只有一份满足业务结构的情况。明确的 think/analysis 区域不参与选择。默认输入上限为 2,000,000 个字符、扫描预算 4,000,000、嵌套深度 128、候选数 32；超限返回 resource_limit，不能只检查前缀就判成功。Markdown 报告兼容入口单独声明忽略围栏外的数字引用标记；围栏中的数组及实际 JSON 对象仍接受结构检查。

结构约束在展示清洗前执行。claimId、taskId、证据引文、反证锚点及 verdict 不经过全文清洗。主张、回答关系与反证合同保持原有严格语义。取消 claim_validation 的硬编码输出帽，显式 `maxTokens: 0` 不继承 provider 默认上限；其他用途的输出配置不在本轮统一取消。

## 调用与恢复

共享边界已接入主张校验、canonical report、叙事校验、规划器、来源评估、gap support、旧动作策略、来源数组过滤、claim entailment 和 benchmark Judge。报告 Markdown 回退必须尊重结构化候选的失败，不能靠文本正则或展示清洗绕过歧义。

失败原因区分 empty、truncated、no_complete_json、invalid_json、ambiguous_result、schema_invalid、resource_limit。确需重试时，仅传安全类别及现有白名单结构反馈；同一响应内能成功解析时不增加调用。预算、取消、基础设施及未知用量错误继续向上抛出。已返回但结构失败且用量未知时保留预约并暂停。

`structuredResponseVersion=1` 参与主张判断缓存、entailment 缓存、gap support 缓存、正文检查身份及冻结报告恢复条件。旧未完成报告须在当前协议下重验，已完成 revision 直接恢复。底层原始回执仍按实际请求匹配以支持重新解释，恢复时保留 finishReason 和用量是否已知，账本已确认调用只结算一次。

Judge 在隐私字段投影前选择并校验答案，拒绝响应只保存哈希、用量和安全解析回执。`quality-judge-10` 与旧版校准、policyHash、请求身份隔离；旧分数、曝光、失败及冻结套件不改写。机器生成的配置、manifest、CLI 输出及页面嵌入 JSON 继续严格读取。

## 验收方式

新增解析器边界测试、生产调用链测试、恢复及预算测试、Judge 持久化测试，并将关键用例登记为 V24 必需场景。固定种子的往返覆盖及恶意超长围栏测试验证扫描边界。

真实失败响应仅在本地离线使用：第二轮 llm-70 / llm-71 必须通过原主张结构合同；第一轮 llm-49 / llm-50 必须保留截断拒绝。`scripts/verify-structured-response-replay.mjs` 只读取调用与输入，返回结构摘要；不发请求、不结算、不改历史运行状态。私有响应、正文、预算和运行目录不提交。

完整验收使用 `npm run verify:programmatic -- --output-dir <new-local-dir>`，重新执行测试、lint、build、diff、外网隔离探针及必需场景。历史产物回归在独立副本中执行完整性验证与故障注入。

## 首轮验收发现

第一轮统一验收保留为失败：lint、build、diff 通过，引擎兼容测试失败。原因是旧版字符串脚本替身没有声明用量，却依赖结构失败后的重试/降级；新规则会将其视为未知用量而暂停。已在旧版测试辅助层声明与原请求分配一致的固定合成用量，显式元数据响应、未知用量对象与异常保持原样。三个辅助层测试确认没有把故意缺失用量的响应转换成已知调用；生产未知用量检查未放松。修正后引擎全量 778 项通过。

应用侧额外运行 529 项，首轮唯一失败同样来自旧版脚本替身；辅助层修正后该用例单独复验通过，最终以统一验收的完整重跑为准。
