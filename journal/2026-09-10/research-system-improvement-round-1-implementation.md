## 真实裁判校准

原 20 条保留为开发集，新增 20 条保留集；在调用前冻结身份，均为自写的 Oriel 虚构资料。未改变原答案标签。无人工复核。

| 指标 | 结果 |
|---|---:|
| 开发集一致率 | 19/20，95% |
| 保留集一致率 | 18/20，90% |
| 全集一致率 | 37/40，92.5% |
| 已知重大错误误放行 | 0 |
| 模型请求 | 80 |
| 确认 tokens | 62,352 |
| 未知预约 | 0 |
| 活跃模型调用时间 | 约 289 秒 |
| 本阶段上限 | 100,000 tokens / 30 分钟 |
| 完整校准门槛 | **未通过** |

未通过的具体原因：

1. 保留集的一条错误断言放在 Markdown 标题中，被模型当成纯标题，完全漏提取。即使总体一致率达到 90%，也不能视为完成全部核验。
2. 一条吞吐量推导、开发集的一条网络文件系统保证，被判为 incorrect；资料实际只是没有给出相应依据，预设标签是 unverifiable。模型仍会混淆“没有证据”和“有反证”。

该保留集已经被查看，后续若据此继续调整裁判，应记录其已成为开发数据，并使用新的独立保留集和新的裁判协议身份。当前轮次没有追加校准版本或预算。

## 操作入口

以下为入口说明，本轮未执行重评、重建或新真实批次：

- `npm run benchmark:quality -- calibrate --output-dir <固定校准目录>`：同一版本总上限 100,000，逐项缓存和墙钟跨恢复保留。禁止换目录来重置本轮预算。
- `score --campaign <原批次> --gold-dir <金标准目录> --calibration <通过的校准文件> --evaluation-dir <新评测目录>`：必须先过校准；新目录独立于原评分。
- `rebuild --campaign <原批次> --baseline-evaluation-dir <已完成的新基线评分目录> --calibration <文件> --output-dir <独立重建目录>`：不接收 gold 参数，固定第一次重复的四个 case。
- `improvement-gate --gate-config <JSON>`：读取 baselineCampaign、rebuiltCampaign、baselineEvaluationDirectory、rebuiltEvaluationDirectory、calibration、regressionChecks；路径相对配置文件。检查当前 runtime hash 与回归记录、评分身份、原始输入 pin、覆盖增量和核心点退化。
- 新候选批次 `plan` 使用 `--improvement-gate-config <JSON>`，把门槛保存到 campaign；后续 `run` 必须通过该门槛。常规历史 campaign 的既有 CLI 行为保留。
