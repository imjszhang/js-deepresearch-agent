## 5. P1：排版与事实分离，闭合补提取流程

### 数据合同

程序生成固定 block/unit ID、原文范围和排版提示。heading、table、paragraph、bibliography 等只描述容器，不决定 facts 必须为空。一个标题既可以是纯组织标签，也可以包含一个或多个事实。

事实提取输出包含命题、kind、原文摘录及明确的 UTF-16 起止位置、引用键。位置必须与原文逐字一致；重复摘录不能再一律绑定到 indexOf 的首次出现。表格行保留表头、列含义和所属上下文，公共条件也不得在拆分时丢失。

事实 ID 由规范化内容及位置确定，复核引用稳定 ID。相同事实多次出现时保留全部 occurrences；每个出现位置仍参加遗漏检查，不靠合并命题掩盖某处条件或引用差异。

### 有界状态机

`初始提取 → 逐单元遗漏复核 → 定向补提取（最多一次）→ 最终复核 → 完成或待审`

- 复核返回 missing 的具体 unit ID；补提取只处理这些单元及必要上下文，不重新生成整篇事实列表。
- 补提取保持已接受事实，新增或拆分事实必须指向原文；修改旧事实需声明替换关系并重新验证受影响的覆盖关系。
- unknown 不是补提取邀请：不能确认的内容保持待审；布局判定也不得把事实性标题当作纯标签直接跳过。
- 最终复核检查原块全部单元，保证补提取没有遗漏或破坏之前已覆盖的内容；完全未受影响的其他块复用结果。
- 补提取一次后仍存在遗漏、无法唯一定位的摘录、结构失败、预算不足或调用结果未知，则保留事实和原因，extractionComplete=false。
- 纯标题、参考文献元数据可以经复核确认没有断言。空技术事实分母可为 N/A，不能伪造事实来凑非空。

重点文件：`report-facts.mjs`；必要时把覆盖复核与补提取拆成小模块，避免继续堆积单函数。

验收：已暴露的事实标题正常进入核验；模拟故意遗漏时补提取有效；补提取仍失败时如实待审；未受影响事实与引用不丢失；同一状态恢复不会重复执行已完成阶段。

## 6. P2：证据关系先行，程序派生真值

### 技术断言

模型不再直接决定最终 truth，而是返回与命题对应的结构化关系：

- full_support：证据支持完整命题及必要条件。
- partial_support：证据只支持预先明确的一部分。
- contradiction：存在同对象、同版本及兼容条件下直接不相容的证据。
- not_addressed：材料没有覆盖该命题。
- uncertain：关系不能可靠确定，或存在未解决冲突。

支持、部分支持与反证必须附具体证据 ID、原文摘录位置和对象/版本/条件关系；只给一个包含整个手册的 G1 不能直接通过。摘录、引用和版本先做程序校验，语义关系再接受模型判断。

事实核验主要提供可用正文与锚点，不把 gold 的 expectedAnswer/commonErrors 当作事实证据。正常评分点匹配仍可读取 rubric，不改变金标准。

| 有效证据关系 | 程序 truth |
|---|---|
| 完整支持，且无未解决反证 | correct |
| 确认部分支持，且无决定性反证 | partial |
| 明确反证，且不存在未解决的同条件支持冲突 | incorrect |
| 已完成检查、无支持也无反证 | unverifiable |
| 关系不确定、证据互相冲突未解决、结构或检查未完成 | pending_review |

“手册不提供性能测量”可支持关于手册内容的归因陈述，不能反驳一个未经测量的性能数字。材料未覆盖其他版本，也不能用当前版本的不同结论反驳它。citation unsupported 与 fact incorrect 始终分开。

程序不能仅凭摘录存在证明逻辑关系正确；本轮用成对的真实模型测试验证这一语义边界，不宣称结构合同已经完全解决推理错误。

### 运行状态断言

把执行证据展开成可寻址字段，区分 known、missing、unknown。比较必须指向明确字段及可验证的断言值。

- sourceReads、documentVersions、passages 是不同指标，不得相互替代。
- null/缺失不是 0，不能支持或反驳具体数值。
- 精确计数、枚举状态等在字段已知且映射明确时使用确定性比较。
- 字段与自然语言断言关系不明确则待审；已明确字段但没有记录值则 unverifiable。
- 元数据不能证明产品技术能力。

保持现有核验调用的返回接口兼容下游计分，新增关系信息用于审计。majorError 继续受固定 critical rubric 约束，不能通过把标签改为 partial 来躲避关键错误。

重点文件：`evaluate.mjs`、`statements.mjs`、新增证据关系映射模块、`judge.mjs` 的输出字段白名单。

## 7. P3：尝试次数、恢复与正式门禁

### 尝试次数

取消 Judge 内层两次与 reviewItems 外层两次叠乘的隐式重试，使用持久化的阶段/项目尝试计数：

| 阶段 | 每个项目最多被派发次数 |
|---|---:|
| 初始提取 | 2，包含结构修复 |
| 首次覆盖复核 | 2 |
| 定向补提取 | 2，且只允许一个语义补提取阶段 |
| 最终覆盖复核 | 2 |
| 证据关系验证 | 2 |
| 评分点匹配 | 2 |

批次请求消耗其中每个项目的次数；拆批不能绕过该计数。预算不足而未真正派发的请求不消耗次数，但不能无限拆分重试。未知结果不自动重发。

### 恢复

- 每阶段保存输入身份、已接受项目、未完成项目、尝试计数、预算与下阶段边界。
- 响应落盘后再结算；响应已落盘的中断可恢复解析，不重发也不双结算。
- 预算耗尽或语义修复耗尽的 pending 是本轮待审结果，恢复命令不能给它额外次数。
- 若此前未知调用已有可校验响应，应允许读取并完成该阶段，不能被缓存中的 provider_pending 永久挡住。
- score.json 是输出快照，不是无条件的“无需继续”标志；只有身份相同且已完成的评测可直接返回。仍有可恢复阶段时，从阶段状态恢复并重算快照。
- CLI 状态使用整体 metrics.pendingReview，而不只检查提取和 rows，避免未映射到评分点的待审事实或引用被显示为 evaluated。
- 校准目录使用单写者锁；整个 suite 共用总账本与阶段额度。

### 门禁

集中实现校准资格校验，供 score、rebuild、improvement-gate 共用。正式评测需要：judge/scoring/schema/模型及受测代码身份一致、事实校准通过、完整评分校准通过、无非预期待审。

旧版 calibration=true 不能因只改版本字段而放行；绑定完整 suite hash、阈值、子阶段结果、已冻结实际调用参数与代码哈希。旧输出保持不可变，不迁移旧分数冒充新版本。

## 8. P4：校准数据与独立 oracle

### 预设断言合同

每个样本保存私有 expectedAssertions：原文最小断言范围、必要条件范围、预期 kind、truth、引用状态、critical 标记。完整报告另存 expectedCriteria、预期 points/evidencePoints、预期指标或明确比较关系。

一个报告可以同时有 correct、incorrect、unverifiable，以及运行状态或建议。不能再只检查“提取结果非空且全等于一个标签”。必须核对预设断言是否全部出现、是否新增虚构断言、是否有错误合并、是否保留所有出现位置。

优先通过原文范围和预设断言槽建立一一对应。不能把一个宽泛 quote 同时算成多个独立断言均被正确提取；无法唯一对应的项目不自动算通过。复杂同义或拆分争议明确列为待裁决，不另请同一个模型生成一个“通过”结论。

空技术分母、纯状态报告、明确预期被拒绝的离线故障用例有各自 oracle，不能机械套用 observed.length>0。正常真实校准样本不靠未预期 pending 获得正确分。

### 固定样本规模

所有已暴露 60 个样本保留为开发资料，添加与修复相关的离线合同测试。真实模型开发回归选择下列固定 20 个样本，覆盖七个已知失败及正确、错误控制项：

- 原开发：cal-01、02、03、04、08、10、15、16、17，共 9 个。
- v3：holdout-27、28、31、39，共 4 个。
- v4：v4-h01、h02、h03、h06、h10、h13、h19，共 7 个。

不把这些样本纳入留出通过率，原始输入与预期标签保持；迁移到逐断言 oracle 时需检查归因、建议及条件范围。发现原标签存在实际歧义，必须在首次模型调用前记录并解决，不能见到结果后改标签。

新留出集分两部分：

1. **20 个断言校准样本**：覆盖标题/表格/建议/总结/限制；至少 4 个含混合真值或复合断言，至少 4 个检查未知与反证的边界，至少 2 个检查缺失运行字段，至少 2 个检查错误引用。类别可重叠，预设标签保持足够正负及未知控制。
2. **14 个完整评分报告，组成 7 个预设对照组**：所有报告走生产 evaluate 链路，共用真实证据构造和计分代码。

| 对照组 | 应观察到的结果 |
|---|---|
| 完整答案 / 删除部分答案 | 固定分母下对应覆盖分下降 |
| 正确版本和必要条件 / 错版本或缺必要条件 | 对应核心点不得满分，决定性条件不允许 partial |
| 正确引用 / 替换为不支持的引用 | 真值可保持正确，证据分下降 |
| 原答案 / 增加无依据断言 | 核心覆盖不虚增，准确率与验证覆盖率按固定 oracle 下降 |
| 正文已回答 / 正文仅状态、答案只在附件 | 后者正文答案覆盖为 0，技术分母按预设为 N/A 或 0 条 |
| 解释版本冲突 / 未解释冲突 | 未解决冲突不能获得对应证据覆盖分 |
| 预先允许的次要遗漏 / 不允许 partial 的同类遗漏 | 分别得到预设 partial 和 0 分，不能由模型自行决定容差 |

新内容至少使用两个新虚构证据包，不能只把 Oriel 换名字。显式正反证、未知字段、两个版本及条件均由短正文直接表达。适度控制篇幅以让预算用于检查语义，而非无关上下文。

全部标签由 agent 预先核对、保留依据，不称为 human_reviewed。新样本设计与阈值先冻结；实施者知道题目内容，故不宣称严格双盲或统计泛化。

## 9. P5：验证矩阵与执行顺序

### 离线检查

| 类别 | 必须覆盖 |
|---|---|
| 提取 | 有/无引用事实标题、表格上下文、混合真值、建议前提、纯标签 |
| 位置与去重 | 同一摘录多处出现、共享条件、复合句拆分、宽 quote 不能替代多个事实 |
| 补提取 | 成功补全、只处理缺失单元、有效旧事实不丢、最多一轮、持续遗漏待审 |
| 证据 | 支持/反证/未涉及成对用例；正文不存在摘录、版本不匹配、未解决双向证据 |
| 状态 | 0 与 null 不混用，读取次数与文档数不混用，元数据不证明技术能力 |
| 计分 | 7 类对照；固定分母、critical、partial、conflict 和引用分别验证 |
| 恢复 | 每阶段响应落盘后中断；零重复调用和结算；未知预约保留；不重置尝试次数 |
| 隔离 | 重复留出/已暴露留出、改标签改代码、混用校准身份、并发写者均拒绝 |
| 门禁 | 只通过单句真值但评分链路失败时，score/rebuild/live 都不能放行 |

离线通过后运行 npm test、npm run lint、npm run build。同步到 PR 后要求对应最新提交的 Node 20/22 CI 通过；原提交的绿色 CI 不能替代新代码的验证。

### 真实模型执行

1. 确认当前模型身份和生效参数，默认保持 qwen3.8:27b-mlx；冻结 endpoint 的脱敏身份、temperature、reasoning 设置及请求输出限制。凭据只从当前环境绑定。
2. 静态验证全部 54 个样本、证据、oracle、阶段顺序和预算；保存代码/配置/样本/计划哈希。
3. 先执行固定 20 例开发回归。七个已知失败必须全部修正，20 例都须匹配且无非预期待审，才进入留出阶段。
4. 开发阶段未过：本轮停止，34 个留出样本保留未执行状态；提交失败分析，不自动修改后再跑。
5. 开发过关：用同一冻结版本依次执行 20 个断言留出和 14 个完整评分报告。某个语义判断错可继续完成本轮固定诊断集合；服务故障、身份漂移、未知调用阻断或阶段预算不足时暂停，未执行项目保持可见。
6. 完成后复核代码和输入哈希没有变化，对比固定开发样本，按原始分组汇总留出结果、成本及修复调用比例。

CLI 可扩展为 `calibrate --suite <v5-suite.json> --output-dir <本轮目录>`，suite 控制阶段和上限，同目录重复调用只恢复；另提供只读 validate/summary。该形式为待实现接口，现有命令尚不支持此 suite 流程。旧参数入口不允许绕过新版校准门禁。

## 10. 本轮拟定预算与停止规则

以下额度属于下一轮计划，当前未执行。它不沿用 v4 剩余额度，也不包含后续真实调研预算。实施时在首次调用前写入 suite 和总账本。

| 阶段 | 样本数 | 确认用量加未知预约上限 | 累计调用墙钟上限 |
|---|---:|---:|---:|
| 真实开发回归 | 20 | 60,000 token | 15 分钟 |
| 新断言留出 | 20 | 70,000 token | 20 分钟 |
| 完整评分留出 | 14 | 90,000 token | 25 分钟 |
| 总计 | 54 | **220,000 token** | **60 分钟** |

预算依据：v4 的 40 例消耗约 8.7 万 token；本轮新增证据关系合同、定向补提取和 14 个完整评分报告，预留到 22 万。它是保险上限，不是消耗目标，也不构成必能完成的保证。

- 逐调用仍先做保守输入/输出预约。所有重试、复核、补提取都归入对应阶段和总账本。
- 单次请求最多 180 秒；阶段墙钟跨重启累计，未知耗时保守记录。
- 各阶段额度不自动互借；不得通过缩短困难样本、删除事实或更换输出目录伪造完成。
- 最多执行一个 v5 冻结候选，不安排预算外实时调试或第二轮盲测。代码改变即需要新身份和新轮次，原结果保留。
- 不自动重发结果未知的调用；可用已有落盘响应恢复结算。不能解决的未知调用保持预约并结束本轮为未完成。
- 新校准超过上限、环境失败或输出不完整时，报告验证未完成及原因，不能将其解释为模型质量已达标。

## 11. 明确验收门槛

### 代码验收

相关离线回归、全量测试、lint、build 及新提交的 Node 20/22 CI 全部通过；不存在放松证据、重置预算、丢失已接受结果或绕过校准身份的路径。

### 校准验收（全部满足才通过）

1. 固定开发集 20/20，含七个已知失败全部修正。
2. 新断言留出至少 18/20 完整匹配。样本匹配包含全部预设断言及其真值、必要类别和引用状态，不能只算其中已提取的一部分。
3. 所有应出现的留出断言与关键条件覆盖完整，无未解释的虚构断言、遗漏或非预期待审；混合真值样本也满足。
4. 错误/未知断言不得被判 correct；预先标记的未知与反证边界关键用例不得把 unverifiable 判 incorrect。
5. 完整评分留出 14/14 达到预设逐评分点结果与对照关系；确定性数值仅容许计算浮点误差，不设事后容差。
6. 处理结果、实际用量、尝试次数及版本身份完整；无预算或环境导致的缺测。缺测不能从分母移除。

输出分别给出代码回归、断言校准、完整评分校准和总体资格，不能把它们压成一个没有解释的 passed 字段。正式消费者使用总体资格。

校准通过只证明在这些固定任务上评测器达到预设门槛，不等于调研系统整体质量已经提高。
