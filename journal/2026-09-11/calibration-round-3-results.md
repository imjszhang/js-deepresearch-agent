## 实现

- `quality-judge-6`，evaluation schema 4，calibration schema 3；定位协议和运行指标定义均为版本 1。计分仍为 `quality-scoring-2`。
- 新增共享定位目录：原始文本 hash、归属、正文版本和原始偏移参与身份。模型选择 `unitId + quote` 或已提供的 `fragmentId`，程序计算并验证 UTF-16 区间。数字位置、伪造 ID、跨归属、错目录、改写摘录及未消歧重复摘录均拒绝。
- 报告断言、共享上下文、gold 证据及引用正文统一使用定位器。引用只能使用自身的 passage，不能借其他引用或 gold 来获得支持。
- 去掉 7,000 字符机械切块，保留完整段落容器和行单元，不截断代理对。过长输入若无法在预算内提交，保持待审；不声称完成覆盖。
- 提取结构修复保留已经成功定位的候选，失败兄弟候选不会清空它们；重复摘录返回程序生成的候选 ID。每项目每阶段仍最多两次派发，语义遗漏补提取仍最多一次。未知覆盖不自动触发补提取。
- 运行指标定义明确区分阅读预算计数、成功正文读取次数和正文版本数。历史成功读取总数没有完整可信记录时固定为 missing，不能用预算次数、HTTP 状态或正文数补造。
- 响应回执与规范候选分别保存；身份绑定定位/指标版本和文本。恢复复用已有响应，未知用量保留预约。终态恢复直接核对账本后返回。
- 实际校准之前冻结计划 hash、代码和测试文件清单、依赖锁文件、离线验证记录、suite 和 oracle、模型参数及历史暴露身份。正式评分、rebuild 和 live 门禁通过共同资格检查拒绝不兼容或不完整的校准。

定位成功仅证明摘录位置真实。断言忠实性、否定/版本/条件、支持与反证仍需语义校验；本轮没有把位置成功等同于研究结论正确。

### 保留的失败与原因

对 16 个证据核验调用进行了只读离线诊断：从当前冻结的生产函数重新构建请求，并逐字节匹配归档调用 hash 后读取已保存响应，没有额外模型请求，也没有改写正式结果。

1. **冗余引用字段合同冲突。** `cal-08 / cal-10 / cal-15` 的主张关系分别返回 contradiction / contradiction / not_addressed，但 unsupported 引用仍带 passage ID；当前合同要求非支持引用的 passageIds 和 evidence 为空，因而整体保持待审。10 份响应出现非支持 verdict 搭配非空 passageIds；计数包含重试及其他样本，不能相加为独立失败样本。
2. **解析状态与支持程度混淆。** `cal-16` 的引用实际已解析，模型却标 unresolved；两次响应均发生。引用解析状态应由程序决定，不能与“该版本没有支持证据”混为一谈。
3. **未知边界仍有语义错误。** `cal-17` 将“手册没有提供该保证”判断为 contradiction；冻结 oracle 要求 unverifiable。它同时给 unsupported 引用附上反证锚点，被现有非支持字段合同拒绝，最终保留 pending_review。不能仅清空冗余字段就宣布这个样本正确。
4. **目录选择仍会出错。** `cal-02 / cal-04` 首次核验分别存在错误的 unit/evidence 选择或 citation evidence ID；第二次调用修复并完整通过。程序已拒绝这四条无效原始锚点，没有自动搜索其他来源来补齐。
5. **预算规划不足。** 定位目录保留了全文容器、行单元及既有文本字段；核验阶段占实际 token 的约 68.2%，加上结构重试和保守预约，60,000 token 开发上限没有覆盖全套样本。这是本轮验收失败的一部分，未通过追加额度掩盖。

未发现需要在本轮改写 oracle 的明确依据。冻结后没有调 prompt、改标签、删样本、修改阈值或另建候选重跑。

## 验收结论和后续边界

- 程序定位、指标定义、缓存恢复、版本隔离已实现并通过离线验收；真实已接受的锚点可精确还原。
- **开发、留出、完整真实评分和正式资格均未通过本轮总体验收。** 新的指标语义和剩余困难案例不能标为已实模修复。
- 正式门禁对本轮结果仍明确拒绝，Google 批次及旧报告后续实验没有启动。
- 下轮优先统一引用合同：由程序确定引用能否解析、从合法定位结果派生证据归属；区分“核对过的片段”和“支持/反证锚点”，减少模型填写互相矛盾的字段，同时保留 not_addressed 与 contradiction 的独立语义约束。
- 随后消除重复传输的文本、对结构失败提供具体反馈，并在下一份计划中重新核算完整开发集的预算和预约。任何新候选需重新冻结；本轮保持原结果。
- 代码仍未提交，PR 保持 Draft；同步后的 Linux Node 20/22 CI 仍未验证。
