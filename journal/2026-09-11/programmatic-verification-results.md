## 首轮失败与实际修复

首轮统一验收没有通过，失败记录保留。它发现了以下问题：

1. API 测试隐式启动监听，碰到受控回环绑定时存在时序问题。改为显式创建服务器、等待监听就绪和清理；同时修正网络守卫把 HTTP path 当作 Unix socket 路径的处理。
2. 两项预算测试直接把历史 v8 suite 交给新协议。改为在临时目录复制并更新必要协议元数据，保留原预算断言和旧版本拒绝测试。
3. lint 扫描了本地历史运行脚本。将运行产物目录加入 ESLint 排除规则，没有修改历史脚本来消除错误。
4. 四次隐含连接来自一个搜索预检测试和一个开启 full fetch 的探索测试。补齐明确的 socket / 正文测试替身，并断言替身被实际使用；没有放松外网隔离规则。

此外，固定种子测试发现并修复了真实恢复缺陷：一个调用的迟到回执恢复后，之前未派发的预算待处理组件没有及时恢复调度。现在在恢复原 flight 后重新判断这些组件，不重置结构尝试次数，不重发已接受项，不重复结算回执。

上述修复先经定向测试，再以同一统一入口重跑，最终产生通过记录。
