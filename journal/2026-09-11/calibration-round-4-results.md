执行日期：2026-09-11。基于未提交的第三轮工作继续，未修改研究运行时、探索下限、原研究产物或 v5/v6 历史结果。本轮唯一候选为 quality-judge-7 / evaluation schema 5 / calibration schema 4；评分公式仍是 quality-scoring-2。真实校准按[冻结计划](calibration-round-4-plan.md)执行，首次调用后不改源码、测试、提示词、样本、oracle、阈值或预算。

## 实现

- 把事实真值和每个引用拆成独立组件。模型只选择证据关系与原文锚点，真值、引用是否存在及对应来源 ID 由程序生成；不再要求模型同时生成相互依赖的重复判断。
- 增加独立语义复核，隐藏初判，分别核对研究对象、版本、条件、产品属性/文档表述以及命题和证据能否同时成立。语义分歧保留待审，不在规则层改成期望标签。
- 组件依赖和原始调用单独冻结。中断时复用原请求及原证据版本；已完成的事实或引用不因同批其他组件失败而重试。有效反证即使遇到覆盖不完整也继续保存。
- 正文按内容去重传输，定位单元与覆盖行通过范围引用正文；相同正文的不同来源身份仍独立。单次预约继续使用输入 UTF-8 字节数加输出上限，未知调用保留预约，不按零消耗处理。
- 增加 `calibration-budget` 静态预检、14 个明确边界诊断及版本化正式门槛。静态预检只证明已知提取请求可准入，不把后续模型相关用量估成确定值。

- `relation-boundary-14`：模型把“未提供独立测试材料”推成与“独立测试建立结论”矛盾。缺失材料不能证明测试或结论不存在。系统因两次判断分歧而保留待审，阻止了错误确认；这不等于模型已正确理解证据边界。

这两项都没有错误确认，也都没有完成正确核验。边界门槛未通过，因此固定开发诊断结束后不会进入留出。

提取流程完成、位置有效、语义核验完成和 oracle 完整匹配是不同指标。V7 的 22 个位置都精确对应原文，但只有 21/22 个预期断言满足所需上下文锚点；其中一个跨句指代仍丢失共享上下文。因此不能把“20/20 提取流程完成”当成“提取质量全部正确”。本轮已决定的真值没有出现与已覆盖 oracle 相反的结论，也没有关键错误接受；这只是这批已覆盖样本的观察，不能推导成跨领域可靠率。

| 未通过开发样本 | 实际原因 | 验收结论 |
|---|---|---|
| cal-15、v4-h06 | 初判把未提供性能测量当成反证，独立复核判 `not_addressed` | 对应事实与引用的初判错误被拦截，最终事实与引用仍待审 |
| cal-17、v4-h13 | 初判把文档未提供保证当成对产品属性的反证；复核判 `not_addressed`，条件另有不确定 | 没有把未知落成“错误”，也尚未完成正确的 `unverifiable / unsupported` 分类 |
| v4-h10 | 第二条断言补全了实体和版本，但未保存第一条中实体/版本的上下文锚点 | 两个断言文本均已提取，真值与引用判断正确；共享上下文不可追溯导致一个 oracle 断言不覆盖，不能按漏掉整条断言或杜撰新断言解释 |

剩余工作集中于两类：让初判和独立复核稳定区分缺证据与直接反证；让跨句实体、版本和条件补全必须绑定原文上下文并经覆盖复核检查。边界诊断另显示，辅助范围分类本身也会误拦截正确反证。本轮没有更改这些失败标签、删除范围门槛、自动用第二次答案覆盖初判，或新增实模尝试来掩盖失败。后续需要新的明确方案与冻结候选，不能把本轮结果改成通过。
