# Review 后三项修复

后续真实校准已单独执行；见 [v4 真实校准结果](calibration-v4-results.md)。以下记录保留代码修复完成当时的范围与验证状态。

本次仅实现 review 确认的三项代码问题及必要的版本隔离。未提交代码，未运行真实模型校准、重评、固定正文重建或新 Google 调研。既有修改、历史结果和预算记录保留。

## 结论绑定去重

原子候选的 ID 包含摘录，主张 ID 则由命题、条件、版本及支持片段等生成。相同结论采用不同摘录时，原实现会产生一个主张和两个相同任务绑定，无法满足回答关系校验的唯一 ID 合同。

现在按 `(taskId, claimId)` 合并原子绑定，保留 required 和缺失条件；不同任务仍独立校验。多个任务共享主张时，反证引用取并集，避免后一个任务覆盖前一个任务的反证。没有放松校验器的唯一性要求。

回归覆盖不同摘录的重复候选正常生成报告、只校验一次，以及共享主张保留独立任务与反证。

## 提取完成度复核

正文分类返回空事实数组会进入有界修复，无法修复则待审。每个已接受块额外调用独立的 `audit_extraction`，检查固定的非空行 ID，逐行判断所有断言是否已被提取，包括标题、表格、总结及建议中的事实前提。

复核必须返回每个行 ID 恰好一次。`covered` 要关联与该行摘录范围实际重叠的事实；`missing`、`unknown`、结构错误和预算或服务故障都阻止 extractionComplete。已经提取的事实保留，不因复核失败丢失。带数字引用的 Markdown 标题不能用 non_assertion 跳过；纯组织标题和参考文献元数据仍可经独立复核排除。空报告不能标记提取完成。

复核与原提取共用 Judge 的用量账本、未知预约和墙钟限制，逐项缓存也参与恢复。新增复核会消耗评测预算；未提高既有上限。语义判断仍是机器草稿，逐行复核并不构成实际模型提取零遗漏的证明。

评测协议升级为 `quality-judge-4`，计分公式维持 `quality-scoring-2`。新版本不会接受旧校准或旧评分缓存。校准入口要求显式传入 `--holdout-file`，文件须声明当前 judgeVersion，至少含 20 个 holdout 用例，且不得与开发集或已暴露的 v3 留出集正文重复。该检查能防止直接重用及仅改版本号的重用，不能代替对样本独立性的人工设计。

回归覆盖空提取修复、事实标题漏检、表格部分漏检、建议事实前提漏检、有效非断言、遗漏行 ID、错误摘录关联、复核不确定或服务失败，以及真实 Judge 类的序列化、缓存和预算恢复。测试中的 LLM 均为本地替身。

## 启动阶段恢复

启动响应落盘后中断、尚无探索步骤检查点时，start 分支现在先启用原始启动边界后的回执恢复，再进入 run。新启动检查点保存 recoveryCheckpointId，恢复时再次中断也不会把边界移过尚未应用的旧响应。

回归模拟首个 research_profile 响应落盘后取消、恢复时业务搜索再次失败、再恢复成功。确认不再次调用 research_profile、原响应不被覆盖、已确认用量只结算一次、无残留未知预约。
