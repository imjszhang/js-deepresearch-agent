# 本地模型沙盒实施记录

## 范围

新增独立 `jdr model-sandbox`，用于测量本地模型服务的等待、生成、并发、取消与结构响应行为。真实调用只由 `run/replay --live` 发起；实现验收使用固定输入和测试自有 loopback 服务，不启动研究、搜索或真实模型。

生产研究的默认传输方式、解析协议和预算语义保持原样。HTTP 公共工厂新增可选传输超时参数；默认值兼容，沙盒显式禁用底层隐含的 headers/body 超时，并使用独立阶段计时。

## 状态合同

传输完整、服务端执行结束、用量已知、结构合格是四个维度。完整但结构失败不自动重试；完整但缺用量可释放容量。超时/断流/客户端取消未确认服务端停止时，保留 pending 并阻止新批次。明确确认设备已空闲后，可通过 `resolve-unknown` 留下人工确认记录并解开资源隔离。

完成结果先落盘再释放预约；同批 worker 全部收束后才释放 OS 锁。持久化故障时，即使已观察到服务端完成，资源隔离状态仍单独披露，不篡改传输事实。

## 指标边界

首内容时间是客户端可观察值。非流式只能测完整 JSON 可见时间，无法还原真实首 token 时刻；服务端排队、输入预处理、冷启动和缓存状态未得到直接信息时一律不推断。Ollama 明示时长单独以纳秒记录。

端到端 completion tokens/s 使用服务端可靠用量除以请求总耗时，包含首响应等待，不称为纯解码速率。网络 chunk 和 SSE event 不是 token。未知用量不填零，失败和未发送的样本保持在计划分母中。

沙盒资源锁只协调采用同资源目录/资源组的沙盒批次，无法限制其它工具对同设备的调用。资源目录默认位于当前工作目录的本地沙盒目录；跨目录调用须显式使用同一资源目录。

## 配置与兼容性

基线默认 1 次预热与 3 组 buffered/stream 对照，共 7 次；并发阶梯默认 1/2。输入规模默认 2048/8192/32768/65536 字符；生成输出额度为测试案例显式参数，默认 0 不增设应用层输出帽。

默认本地队列 5 分钟、响应头与首有效事件各 15 分钟、活动空闲 2 分钟、单调用总时长 30 分钟、批次 2 小时，均冻结且可配置。Node 计时上限、计划文件体积、总输入量和响应字节数均在发送前检查。

修正根包原有的 `workspace:*` 发布依赖：使用对应 workspace 精确版本（engine 1.0.0、wiki 0.1.0），保留 npm workspaces 的本地链接。安装验证使用原样根包和两个本地 workspace 的 tarball，不依赖把新代码先发布到 registry。

## 后续真实模型观察

用户随后授权真实测试，使用当前配置的 `qwen3.8:27b-mlx`，分五个冻结批次完成 24 次请求，确认用量合计 53,419 tokens。所有请求传输完整、执行结束、用量已知；五批产物均通过 `inspectSandbox` 完整性校验。未修改持久配置或旧研究状态，原始运行产物保留在本地忽略目录。

| 测试 | 观察 |
|---|---|
| 基线 7 次 | 1 次预热与 3 组非流式/流式对照全部完成；短输出样本不用于证明流式提速 |
| 输出规模 4 次 | 128 token 约 2.7–3.0 秒，512 token 约 6.3–6.5 秒；均以预期的 length 结束 |
| 并发 8 次 | 相同 512 token 输出任务，每级 4 次；并发 1/2 整组耗时 29.89/24.83 秒，首内容中位数 1.44/6.36 秒 |
| 输入规模 2 次 | 2,048 字符约 4 秒；65,536 字符实际为 45,857 输入 tokens，约 137 秒 |
| 简单结构 3 次 | JSON 对象、精确 ID 集合、枚举规则均通过，不代表复杂研究语义正确 |

长输入请求在 1.67 秒收到响应头、6.80 秒收到首批字节，136.66 秒才出现非空内容。没有服务端队列、预填充或代理缓冲指标，不能据此确定内部耗时归因。并发 2 的吞吐约提高 20%，但等待显著增加；样本量小且缓存和外部负载未控制，只支持暂以并发 1 为保守基准。

已知指标口径：`firstEventMs` 是首个有效进展或结束事件，不是首个协议帧；`maxActivityGapMs` 只从首段非空内容/推理起算。本次长输入仅返回一段内容，该值约 19 毫秒，不包含首内容前等待。后续可补充收包间隔、协议帧分类及首内容前等待指标；当前应结合 headers/firstBody/firstContent/total 阅读。此前 15 分钟的研究调用超时尚未复现，不以本轮通过宣称已修复。
