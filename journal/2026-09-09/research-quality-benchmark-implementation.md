# 调研质量评测实施记录

状态：评测工具已实现并验证，正式 live Google 基线执行中；本文随最终结果更新。没有修改调研引擎算法。

## 已实现

- Redis / SQLite 四种原始问题、确定性顺序的八次运行矩阵。
- 本地标准答案包：每题 20 个评分点，带版本范围、条件、原文 hash 和 UTF-16 锚点。状态为 agent_verified，未冒充人工核验。
- SQLite 3.46.0 独立实验：写者竞争、旧快照升级、checkpoint 与长读、备份完整性四项通过；固定源码 hash、source ID 和编译选项。
- 独立主报告事实提取、金标准匹配、事实与引用分开判断、冲突评价、确定性聚合和人工复核清单。
- 裁判结构约束、有界结构重试、响应缓存、确认用量与未知预约账本；不持久化自由推理或凭据。
- CLI 运行编排、原始问题隔离、固定 manifest/revision、失败保留、会话恢复、Google skill 信任检查。
- 保存证据的候选上下文诊断、逐题重复分布、逐要点版本比较和成本不确定性。
- 经 hash 校验、截止固定 resultRevision 的检查点时间线，记录候选、正文版本、片段、主张和绑定首次出现时的确认用量；不推断历史判断正确性。
- `benchmark:quality` 命令及题库 README；已有 benchmark 与调研 runtime 接口保持不变。

## 当前验证结果

- 评测工具当前新增 41 项测试通过，覆盖少答高准确率、空报告、错版本、错误引用、反证、结构错误、恢复结算、配置隔离、manifest 完整性、时间线版本隔离及裁判缓存/隐私等。
- 全量测试通过：engine 683、wiki 20、应用 290，共 993；lint 和 build 通过。随后针对裁判缺失依据的结构反馈增加了明确枚举提示，41 项定向测试及 lint 再次通过。
- 模型裁判使用当前配置的 `qwen3.8:27b-mlx`。初版 20 个合成样本一致率 90%；真实评分发现模型混用评分点与证据 ID 后，裁判 v2 改为短锚点 ID 并重新校准，一致率 85%，未达到 90% 目标。三处差异均为“不可核验”被判为“错误”；两版均未把预设错误事实判为正确。
- 合成样本由 Agent 标注，包含预先划分的保留样本；所有结果仍明确标注非人工核验。
- 初版校准确认消耗 33139 tokens，v2 校准 32100 tokens，均无未知用量；与研究预算分开记账。旧校准不冒充新裁判的验证结果。
- v2 可输出诊断用评分草案，但校准未达标会强制保持待复核、禁止质量合格标签；数值阈值结果单列。

## 正式基线前暴露的环境与配置问题

1. Google skill 先前的代码升级使已有信任记录失效。CLI 的 doctor/TCP 探活成功，但真实搜索被 `source-content-changed` 拒绝。调试尝试产生 59 次失败搜索且没有正文读取，说明现有 runtime 的探活和不可重试 provider 错误处理仍有改进空间。
2. 检查确认 Google skill 权限声明未变化，来源代码对应已审查的摘要修复；通过 js-eyes 原生 trust 命令更新该技能的 worker 信任，随后一次 Google 搜索返回两项结果。未修改其他 skill 或放宽全局策略。
3. 初版测试协议同时启用总 token 保险丝、保持报告输出无限制。现有 BudgetManager 明确拒绝该组合。评测协议 v2 补充 16000 报告输出上限，并在建立 campaign 时检查，避免执行到报告阶段才发现配置不兼容。
4. 调试 campaign 的失败/取消及预算保留在本地，和修正协议后的正式八次基线分开，不能将恢复或环境修复后的结果替换成原来的成功结果。

这些问题已转为设施防护与候选改进线索，未借机修改被测研究算法。正式结果必须使用相同 v2 协议比较。

## 当前局限

- 诊断使用有限的已保存正文候选，不能因候选未命中而宣称没有公开证据。无法充分归因时标 unattributable。
- 当前实现没有完整的任意新查询离线回放；artifact rescore、合成组件测试和 live Google 各有不同含义。
- 自动评分仍需要复核，尤其是额外事实、证据不足与错误的区分，以及全文事实提取的遗漏。没有人工参与的批次不会标 human_reviewed。
- 两次重复只展示波动，不宣称显著性。真实搜索和网页变化仍可能影响组间比较。
- Google 语言固定为 zh-CN，地区沿用现有浏览器/provider 默认值；当前 CLI 未显式传地区参数，因此不宣称搜索地区和个性化完全受控。

后续评分控制进程等待研究矩阵结束后再执行全部已交付结果的评分与诊断，并生成本地汇总。研究状态、评测状态、校准失败和人工复核状态相互独立；控制进程退出成功也不代表每份评分均完成。
